2. **决策、结果、失败、评估器提取：实现。** 另包含状态、启发式、流程、产物，共八类。
3. **无强制人工审批：实现。** 提取后直接持久化，置信度与生命周期独立控制。
4. **来源追踪：实现。** source URI、记录位置、Event、Episode、evidence ID、历史片段。
5. **第二次任务自动继承：实现并以可执行 fixture 验证。** CLI 包装器与 Claude UserPromptSubmit 自动注入。

8. **生命周期可检查：实现。** CLI、JSON 导出、浏览器查看与审计哈希链。

## 关键实现选择

- 标准库 Python + SQLite：降低初版运行成本；语义模型和存储接口分离。
- 原生日志不保留系统 / 开发者提示和隐藏推理。正常化 Episode 中保留必要消息、动作结果与片段，原始轨迹只通过来源指针引用。
- 规则提取器是可替换的基线，实现明确的类型、候选标记与证据边界。后续可加入 LLM 提取，但不能绕开这些边界。
- 合并优先使用相同类型、范围、归一化陈述和条件，避免模糊语义匹配误合并。冲突 / 状态替代需要显式 `metadata.key`。
- 跨项目域级经验须有三个独立 Episode 和两个项目。三次自述可以构成重复模式候选，但不构成已验证的普遍规律。
- 手工纠正、拒绝和缩小范围优先于后续重复抓取。Pin 不会改变观察时间，也不能恢复过期状态。
- 浏览器只是查看 / 纠正表面；代理正常使用路径不要求每日清理收件箱。
- UI 无 CDN、无外部字体、无前端构建依赖。HTTP 服务只监听 `127.0.0.1`，校验 Host、Origin、JSON 与请求头。
